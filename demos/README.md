# Demos

This directory holds reviewable demonstrations of completed OS outcomes: demo flows, recording scripts, screenshots, browser evidence, and human-review notes.

## Demo Contract

Each demo should identify:

- The ticket and intended user.
- The problem and promised outcome.
- Required setup and safe test data.
- The exact flow to demonstrate.
- Expected success, empty, loading, error, and recovery behaviour when relevant.
- Desktop and mobile checkpoints for user-facing applications.
- Evidence captured and known limitations.
- What requires human review before recording or sharing.

A script or screenshot is evidence only for what it visibly demonstrates. It does not prove deployment, publication, backend correctness, or customer value unless those claims have separate evidence.

Do not store secrets, production customer data, or personal browser sessions here.
