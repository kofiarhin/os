# OS Roadmap

## Product State

- Lifecycle: Exploring
- First-user hypothesis: Kofi
- Product boundary: Standalone; not part of Hibachi
- Architecture and implementation stack: Not selected
- Product authority: `docs/PRD.md` and `docs/SPEC.md`

## Current Goal

Prove that OS can move one real content idea through a governed, inspectable loop:

`idea → brief → approved ticket → skill execution → saved output → review → verification evidence`

The existing TikTok workflow is the recommended first vertical slice because the repository already contains a TikTok skill, relevant brand context, and a saved example output.

## Now

1. Establish the operating backbone: guide, roadmap, review standard, ticket format, customer evidence rules, demo area, and routine definitions.
2. Define one TikTok content ticket with an observable finish line.
3. Run the ticket through the complete operating loop and record evidence.

## Next

1. Compare the first run with the existing ad hoc content workflow.
2. Record friction, missing context, approval overhead, and verification gaps.
3. Repeat the loop with Instagram only if the first run exposes a reusable pattern.
4. Decide whether the validated loop warrants application implementation.

## Later

- Select an application architecture only after workflow evidence exists.
- Add browser-based eyes and preview when a user-facing application exists.
- Promote proven repeated workflows into versioned skills.
- Introduce read-only routines, connectors, and deterministic hooks incrementally.

## Explicit Exclusions

Until separately decided and approved:

- Application scaffolding or architecture selection.
- Production deployment or merge.
- Multi-user collaboration, authentication, roles, billing, or payments.
- Autonomous publishing.
- Live customer-data integrations.
- Active schedules or background routines.
- New dependencies, external services, connectors, or hooks.
- A marketplace for agents, skills, or tools.
- Unbounded or unsupervised execution.

## Evidence Required To Advance

Before selecting the OS application architecture, capture:

- One completed end-to-end ticket.
- The context used and why it was relevant.
- The approved plan and any material changes.
- The generated outcome.
- Verification and review evidence.
- Human-review findings.
- A short assessment of whether OS reduced coordination overhead.

## Definition Of Roadmap Progress

A roadmap item is complete only when its ticket meets its acceptance criteria, required checks are inspected, review findings are resolved or disclosed, and the final state is recorded without overstating implementation, verification, publication, merge, or deployment.
